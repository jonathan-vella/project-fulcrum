# ADR-0002: Cosmos NoSQL Serverless as the primary store

> Generated by design agent | 2026-11-09
>
> Status: Recorded approved design decision; implementation Unverified  
> Date: 2026-11-09  
> Deciders: Project Stakeholders through the actual DEV Gate 2 approval

## Context

[Architecture — Executive Summary](02-architecture-assessment.md#-executive-summary):
> one NoSQL serverless account, Standard GPv2 Hot LRS Blob and private ACR Premium.

[Requirements FR-02](01-requirements.md#core-infrastructure-capabilities) prefer
Cosmos as the document primary and explicitly need no relational database.
[Manifest `document-store`](contracts/sku-manifest.json) records NoSQL Serverless,
one database/three containers, 10GB live data and 20 million RU/month.

## Decision

Record the approved single-region Sweden Central NoSQL Serverless account.
Use private HTTPS via a Cosmos PE, SDK Gateway mode, app MI/native data-plane
RBAC and disabled local keys. Retain paid continuous 30-day backup and the
separately modeled same-region restore exercise; see
[ADR-0006](03-des-adr-0006-same-region-logical-recovery.md).
The 1000RU/s peak is a planning envelope, not sustained demand or a guarantee.

## Alternatives Considered

| Alternative | Benefit | Rejection / trade-off |
| --- | --- | --- |
| Manual shared 1000RU/s | Explicit continuously provisioned capacity | The existing priced comparison has a higher intermittent-DEV baseline because capacity bills for 730h. |
| Add a relational primary | Relational features where needed | Requirements explicitly do not require one; it is outside the approved service set, not a second priced candidate. |

Source: [SKU alternatives](02-architecture-assessment.md#-resource-sku-recommendations),
[SKU comparison](03-des-sku-comparison.md), Requirements FR-02.

## Consequences

- **Positive:** consumption-based RU model suits the selected intermittent DEV profile.
- **Negative:** partition skew/throttling and SDK behavior are untested; monthly
  RU volume cannot establish peak throughput or response-time compliance.
- **Neutral:** application data modeling, authorization and tests belong to the
  application team. A restore creates a new account and requires rebinding.

## WAF Pillar Analysis

| Pillar | Approved trade-off |
| --- | --- |
| Security | MI/native data roles and PE; actual principal scope and key denials require verification. |
| Reliability | Paid continuous backup, but no multi-region HA or regional-loss recovery promise. |
| Performance | Serverless consumption fits the planning pattern; concentrated 20RPS/1000RU/s, indexes and partition distribution need tests. |
| Cost | Lower compared intermittent baseline; backup/restore and temporary target are not treated as free. |
| Operations | Managed document service reduces administration; endpoint/DNS/RBAC restoration still needs a runbook. |

## Compliance Considerations

**Assumed Corp policies—not tenant-verified; DEV Architecture-only.**
Application data and backups stay Sweden Central. No free-tier entitlement,
real-data approval, second database service or geographic exception is introduced.

## Implementation Notes

Validate service-correct private DNS, TLS/Gateway HTTPS, data grants and negative
authorization. Recovery operators and the application team must measure restored
data correctness and endpoint cutover, not just successful account creation.
