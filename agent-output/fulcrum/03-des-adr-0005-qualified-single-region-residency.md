## Context

[Architecture — Decision Summary](02-architecture-assessment.md#-architecture-decision-summary):
> Preserves approved residency and LRS pin; only qualified Entra/ACR exceptions.

[Requirements — Residency constraint](01-requirements.md#residency-constraint)
and the actual [Entra receipt](_meta/02-entra-residency-exception-receipt.json) /

historical absolute restriction for those specific provider behaviors.

## Decision

Keep workload compute, application data, Blob, backups and monitoring in Sweden
Central. Record only the approved qualified European Entra identity commitment,
including documented limited transfers and tenant-provisioning/product
applicability qualifications, plus Microsoft-managed paired-EU registry image/
artifact storage (documented Sweden South pairing). Neither is a customer
geo-replica or application regional-failover design.

Workforce and external Volunteers remain in scope; actual External ID external-
tenant applicability is not established by this documentation.

## Alternatives Considered

| Alternative | Benefit | Rejection / trade-off |
| --- | --- | --- |
| Absolute Sweden Central-only identity and registry storage | Simpler geographic statement | Historical conflict is resolved only by the actual narrow user acceptances; this is not the current approved requirement. |
| Blanket global/paired-region exception or customer geo-replicas | More service/DR flexibility | Not authorized; optional replicas, other-service pairing and general transfers remain outside scope. |

These are requirement-bounded rejected interpretations, not newly priced designs.

## Consequences

- **Positive:** preserves the owner's workload boundary while allowing the
  specifically accepted provider identity/artifact behavior.
- **Negative:** provisioning, product coverage and limited-transfer conditions
  require later secure validation; no absolute no-EU-egress guarantee is available.
- **Neutral:** fictional DEV/GDPR-aligned intent is not legal certification,
  actual tenant compliance evidence or future Production approval.

## WAF Pillar Analysis

| Pillar | Approved trade-off |
| --- | --- |
| Security | Explicit, narrow data-handling boundaries; actual tenant/product conditions remain unverified. |
| Reliability | No workload geo-DR; provider-paired artifacts do not restore application data/compute. |
| Performance | Single workload region limits topology; identity processing is not asserted Sweden Central-local. |
| Cost | No optional customer geo-replication; shared/provider charges are not inferred free. |
| Operations | Exception provenance is explicit; tenant provisioning, policy and service applicability need later reconciliation. |
