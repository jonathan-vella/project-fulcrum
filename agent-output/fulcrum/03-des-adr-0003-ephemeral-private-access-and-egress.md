# ADR-0003: Ephemeral private DEV access with independent app egress

> Generated by design agent | 2026-11-09
>
> Status: Recorded approved design decision; implementation Unverified  
> Date: 2026-11-09  
> Deciders: Project Stakeholders through the actual DEV Gate 2 approval

## Context

[Architecture — Decision Summary](02-architecture-assessment.md#-architecture-decision-summary):
> Selective app platform route; runner-only NAT

[Requirements FR-05](01-requirements.md#core-infrastructure-capabilities) need
reachable private services. The approved
[dependency closure](_meta/02-final-dependency-closure.md) selects controlled
private clients rather than direct physical-phone ingress.

## Decision

Record operator → Standard Bastion/native Entra SSH → private Linux
Standard_D2as_v5 runner/P6 → App/SCM, Cosmos, Blob and ACR private HTTPS.
The new isolated `10.42.0.0/22` VNet has exactly four selected subnet rows;
the [focused diagram](assets/03-des-diagram-network.svg) preserves their CIDRs.
Unused `10.42.1.128/27` is a reserve, not a fifth deployed subnet.

Only the runner subnet uses Standard NAT. App private destinations/configuration
image pull use outbound integration; its permitted identity/control/Monitor
traffic uses independent platform egress for 730h. Do not send the app through
80h session NAT. NAT is translation, not hostname filtering.

## Alternatives Considered

| Alternative | Benefit | Rejection / trade-off |
| --- | --- | --- |
| Project VPN / P2S | Direct remote private routing | Excluded by the assumed Corp hybrid-network floor; not approved access. |
| Public VM NIC or public API | Easier direct client reachability | Violates the accepted private design and baseline. |
| D2s_v5 runner | Equivalent non-burstable 2vCPU/8GiB shape | Existing compute-only comparison selected the lower-cost D2as_v5; no broader alternative workload total inferred. |

Sources: [network/security assessment](02-architecture-assessment.md#-security-assessment-710),
[SKU comparison](03-des-sku-comparison.md).

## Consequences

- **Positive:** private controlled testing/publishing without a public VM/API or VPN.
- **Negative:** access depends on recreated, configured session infrastructure;
  no direct physical-phone test path or always-available access is promised.
- **Neutral:** VM, disk, Bastion, NAT and two service-owned IPv4 IPs assume
  80 provisioned hours. They require **future authorized deletion** to end
  billing; VM deallocation is insufficient and this ADR grants no deletion.

## WAF Pillar Analysis

| Pillar | Approved trade-off |
| --- | --- |
| Security | Native Entra SSH, Bastion-only SSH22, private runner/HTTPS; actual NSG and identity bindings unverified. |
| Reliability | Disposable access reduces persistence; app operation must not depend on session NAT. |
| Performance | Non-burstable runner; 25GB NAT processing is an approved scenario volume, not measured throughput. |
| Cost | 80h access allocation reduces modeled lifetimes only if all billable resources are later removed with authority. |
| Operations | Recreation/deletion discipline replaces a permanent remote estate; extensions/bootstrap/DNS need verification. |

## Compliance Considerations

**Assumed Corp policies—not tenant-verified; DEV Architecture-only.**
Bastion and NAT own public service IPs; the runner NIC does not. Four subnet
NSGs are required; PE network policies are Disabled, so the attached PE-subnet
NSG is not evidence of endpoint-traffic filtering.

## Implementation Notes

Governance verifies actual policy, overlap and DNS ownership; Planner defines
explicit NSG priorities, platform/Bastion rules, PE443, DNS53 and sanctioned
bootstrap dependencies. A later all-traffic app-routing requirement returns
to the owner for persistent-egress reconciliation, not silent redesign.
