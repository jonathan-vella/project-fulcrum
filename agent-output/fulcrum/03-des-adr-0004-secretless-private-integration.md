# ADR-0004: Secretless identity-based private service integration

> Generated by design agent | 2026-11-09
>
> Status: Recorded approved design decision; implementation Unverified  
> Date: 2026-11-09  
> Deciders: Project Stakeholders through the actual DEV Gate 2 approval

## Context

[Architecture — Decision Summary](02-architecture-assessment.md#-architecture-decision-summary):
> No confirmed stored-secret category; preferred Key Vault excluded because Sweden South replication has no exception.

[Requirements FR-04 / FR-07](01-requirements.md#core-infrastructure-capabilities)
require secure identity and image/secret handling; a product preference does
not require an unnecessary vault. Approved
[dependency closure](_meta/02-final-dependency-closure.md) covers every confirmed
DEV credential category through MI, short-lived Entra and platform HTTPS.

## Decision

Record app MI for Cosmos/Blob/ACR, native scoped data-plane grants, short-lived
Entra publisher/operator tokens and platform TLS. Disable registry admin,
local Cosmos keys, Blob shared key/public access and local telemetry auth.
Use four steady PEs and service-correct central private DNS, including SCM
and registry regional data records. Do not add a Key Vault, custom certificate,
CMK or a stored-secret inventory absent from the approved design.

## Alternatives Considered

| Alternative | Benefit | Rejection / trade-off |
| --- | --- | --- |
| Add the preferred Key Vault | Stores secrets/certificates if required | No required stored-secret category; its Sweden South behavior has no accepted exception. The product preference does not override residency. |
| Registry admin / shared keys / long-lived login credentials | Simpler initial credential plumbing | Contradicts MI/Entra and secret-protection baseline; excluded rather than a viable priced option. |

Sources: architecture Decision Summary and
[Security Requirements](02-architecture-assessment.md#security-requirements-for-implementation).

## Consequences

- **Positive:** avoids stored application/login credentials and an unsupported
  residency dependency while preserving secret-management requirements.
- **Negative:** precise SDK, platform routing, registry permission mode and
  principal/grant bindings must work; identity absence breaks startup/access.
- **Neutral:** a newly discovered stored-secret requirement belongs to the
  architecture owner; this ADR does not authorize an inline vault addition.

## WAF Pillar Analysis

| Pillar | Approved trade-off |
| --- | --- |
| Security | Least-privilege tokens and private TLS reduce credential exposure; negative authorization tests remain required. |
| Reliability | Removes secret rotation/storage dependency, but identity/DNS/platform configuration remain serial dependencies. |
| Performance | Gateway HTTPS/private image pulls follow the selected design; no measured latency claim. |
| Cost | No unneeded vault; ACR Premium remains the capability-forced private registry tier. |
| Operations | Fewer stored credentials; grants, registry permission mode and authenticated SDK configuration need owner discipline. |

## Compliance Considerations

**Assumed Corp policies—not tenant-verified; DEV Architecture-only.**
Public Monitor query/ingestion is only conditionally allowed with authentication;
it is not a public API/data exception. DNS DINE assignment alone proves neither
zone/link existence nor working resolution.

## Implementation Notes

Planner/platform owners later bind least-privilege scopes and confirm central
zones, links, PE records, app/SCM resolution and private cold-start image pull.
Application team owns issuer/audience/role enforcement and every application test.
No actual principal, contact, tenant identifier or secret is published here.
