  consumes one address per instance plus Azure reservations and temporarily doubled
  instance addresses during scaling. The guide recommends `/26` headroom. It distinguishes
  selective RFC1918/private routing from all-traffic routing: with all-traffic routing
  disabled, Internet egress is directly from the app. The adopted 730-hour app must not
  depend on an 80-hour runner NAT. Private image-pull routing and actual DNS/MI/SDK
  bindings still require whole-path validation before final pricing/review.
- [Bastion configuration](https://learn.microsoft.com/en-us/azure/bastion/configuration-settings)

  no other resources may occupy it. The proposed `/24` follows the repository's
  greenfield Standard headroom recommendation; this does not change its two base units.
  Bastion's Standard static public IP belongs to Bastion, not the runner NIC.
  Do not infer zone support or zonal SLA: the fetched page labels zone support Preview.

  describes attaching NAT to existing subnet(s)/public IP, requiring no dedicated
  NAT subnet or routing configuration. It permits response traffic, not unsolicited

  this proposal retains the adopted Standard scenario and makes no zone-redundancy
