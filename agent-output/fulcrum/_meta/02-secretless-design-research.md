## ARCH-FEAS-003 — required private image-delivery boundary

[ACR regional storage](https://learn.microsoft.com/azure/container-registry/container-registry-storage)
states that ACR **may also** store registry data in a paired region, except in Brazil South
and Southeast Asia. Sweden Central is not one of those documented exceptions.
This differs from Key Vault's automatic replication: no actual registry or replicated image
has been observed. It nevertheless does not establish the required prohibition on
non-Entra storage outside Sweden Central.

The same page separates optional geo-replication from the regional-storage qualification.
[Zone reliability](https://learn.microsoft.com/azure/reliability/reliability-container-registry#resilience-to-availability-zone-failures)
describes in-region replication and does not remove that qualification. Disabling
customer geo-replication, enabling zones, a regional data endpoint, or a Premium tier name
must not be treated as a single-region storage guarantee.

**Result:** exclude ACR from compliant committed selection until authoritative supported
containment evidence resolves this. Private Link forces Premium **if** ACR becomes viable;
Basic/Standard do not satisfy the private baseline. No fabricated alternative tiers or prices.

The [documented generic private-registry path](https://learn.microsoft.com/azure/app-service/deploy-ci-cd-custom-container#configure-registry-settings)
requires login/password. It does not establish a supported managed-identity alternative.
A self-hosted registry would need its entire authentication, platform HTTPS, bootstrapping,
private pull/push, logging and recovery path proved; it is not silently substituted or provisioned.
An external/public registry or another region is not a compliant assumed alternative.

The preferred registry product is not locked, but **FR-01 container hosting and FR-07 private
authenticated image delivery are required**. Removing those functions would change approved
functional scope. This is a precise capability blocker, not proof the whole workload is impossible.

## Recovery and dependency closure

Cosmos continuous backups are local by default, zonal where configured, and are taken in each
account region. Keep a single Sweden Central account/backup region rather than adding replicas.
Steady-state mutation backup within 100 seconds is a documented behavior, **not a verified
one-hour RPO or four-hour end-to-end RTO**. Restore duration depends on data size; a new-account
restore does not restore private endpoints, firewall/VNet configuration and role assignments.
Reapply approved connectivity, grants and DNS, then rebind the backend and validate access.
The public documentation describes both new-account and supported in-account restore paths;
choose the scenario-supported mechanism rather than treating every restore as identical.

Blob soft delete, versioning, container soft delete and eligible point-in-time restore provide
in-account logical protection. Change feed/protection retention and additional stored versions
are cost scope. LRS does not provide an independent regional disaster copy. The planning targets
cannot be declared achieved during regional failure; no cross-region recovery exception is added.
Data sizes and a scoped recovery exercise remain necessary.
