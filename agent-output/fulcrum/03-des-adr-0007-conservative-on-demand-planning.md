# ADR-0007: Conservative on-demand planning with minimal DEV cost monitoring

> Generated by design agent | 2026-11-09
>
> Status: Recorded approved design decision; implementation Unverified  
> Date: 2026-11-09  
> Deciders: Project Stakeholders through the actual planning inputs and DEV Gate 2

## Context

[Architecture — Decision Summary](02-architecture-assessment.md#-architecture-decision-summary):
> No shared free credits, discounts, invoice-band assertions or changing user usage.

[Requirements — Budget](01-requirements.md#-budget) select on-demand only and a
soft monthly planning range, not a hard cap or spending approval. The existing
[cost report](03-des-cost-estimate.md) and
[COMPLETE 17-line evidence](contracts/02-cost-estimate.conservative-planning-v2.json)
are the authoritative unchanged prices, not new Design estimates.

## Decision

Record the already accepted conservative allocation scenario with no free
allowances/discounts assumed: additional app 1 decimal GB + NAT 5GB = 6GB MGN,
and separate Bastion 5GB, each at its own highest verified paid native meter.
Preserve native GB/TB/Tb distinctions; this is not predicted traffic, invoice
band placement or observed spend. Shared corporate Defender/workspace charges
outside the project boundary remain unknown, not zero.

Retain DEV `minimal` cost monitoring: Consumption budget with effective human
Owner-role recipients, no dedicated cost Action Group or daily anomaly alert.
Operational alerts remain: four static metric series and one 5-minute log rule.
Workspace Insights/Logs share one sanitized 1GB/month ingestion envelope and
explicit 30-day retention; do not double count ingestion.

## Alternatives Considered

| Alternative | Benefit | Rejection / trade-off |
| --- | --- | --- |
| Free entitlements, shared credits or reservation discounts | Lower apparent planning cost | Not accepted evidence/commitment; on-demand and paid conservative allocation were explicitly selected. |
| Enforced dedicated cost Action Group + daily anomaly alert | Additional cost notification controls | Actual DEV `minimal` choice removes only these cost-specific items; operational alerts are not removed. |

Sources: [Cost assessment / routing](02-architecture-assessment.md#-cost-assessment-810)
and unchanged pricing evidence above.

## Consequences

- **Positive:** transparent paid bounds across all 17 modeled billing lines;
  smaller DEV notification configuration without suppressing operational alerts.
- **Negative:** conditional volumes/lifetimes and shared allocations are not an
  invoice forecast; no named team's receipt follows from Owner-role addressing.
- **Neutral:** future usage reconciliation and authorized deletion discipline
  remain necessary. Design makes no pricing call and writes no new cost report.

## WAF Pillar Analysis

| Pillar | Approved trade-off |
| --- | --- |
| Security | Sanitize logs, authenticate ingestion/query and bind recipients securely; public Monitor is policy-conditional. |
| Reliability | Operational alerts retained; budget controls do not establish service availability. |
| Performance | Scenario volume is not measured workload demand; runtime sizing still requires tests. |
| Cost | On-demand conservative bounds avoid assumed credits; retention/restore/transfer/lifetime uncertainty remains. |
| Operations | Existing monitoring team owns access; Planner must verify actual Owner recipient and later alert tests. |

## Compliance Considerations

**Assumed Corp policies—not tenant-verified; DEV Architecture-only.**
No threshold amount is fabricated from the soft range. No public API/data
exception, real contact publication, additional spend or pricing permission follows.
